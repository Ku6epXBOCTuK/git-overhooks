# Backlog

## WIN-001: format-скрипт зависит от GNU-утилит (grep/cmp/mktemp)

**Статус:** открыто, отложено

**Где:** `src/format.template` (и все будущие скрипты в `hooks.d`).

**Проблема:** на Windows `grep`, `cmp`, `mktemp` не входят в системный PATH.
Они есть только внутри Git for Windows (`<git>\usr\bin\`), и Git подмешивает их в PATH
только для процессов хуков.

**Как поведёт себя сейчас:**
- Реальный поток `git commit` → **работает** (проверено): Git добавляет свой `usr/bin` в PATH хука, goh наследует его.
- Ручной запуск `goh hook pre-commit` из терминала → npm-детект (`grep`) может тихо не сработать: `if` короткозамкнётся по ошибке «grep: not found», Node-форматтер пропустится. Rust-ветка не зависит от GNU-тул, пострадает только Node.

**Варианты решения (нужно выбрать):**
1. **Копировать нужные exe к себе** — в `~/.config/goh/bin` (или в отдельную папку) класть `grep.exe`, `cmp.exe`, `mktemp.exe`, ... и в format-скрипте/раннере подключать `PATH` на эту папку. Плюс: самодостаточно, не зависит от расположения Git. Минус: тащим бинарники, лицензии/версии.
2. **Использовать Git'овские утилиты по абсолютному пути** — мы уже умеем находить `sh` рядом с `git` (`<git>\usr\bin\sh.exe`); из того же корня берутся `grep/cmp/mktemp/sed/...` и подкладываются в PATH раннера (`goh hook`) или скрипта. Плюс: ничего копировать не надо. Минус: знаем о расположении Git.
3. **Убрать GNU-зависимость из форматтера** — определять `format` средствами Node (`npm pkg get scripts.format`, npm гарантирован в PATH для node-проектов), заменить `mktemp` на фиксированный временный файл, `cmp` — на сравнение переменных в самом sh (POSIX-встроенное). Плюс: кроссплатформенно начисто. Минус: чуть сложнее скрипт.
4. **Прочее** — например, BUSYBOX-совместимый shim поверх `git` (сложно), утилита `git --exec-path` для libexec-git (там не всё), требовать от пользователя добавить `usr/bin` в PATH (плохой UX), ХРАНИТЬ КАК ЕСТЬ (работает в реальном потоке, но хрупко для ручных запусков).

**Решение проверить:** при первом ручном `goh hook pre-commit` без git-окружения npm-детект не сработает.
