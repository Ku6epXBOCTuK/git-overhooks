# ADR-02: изменение процесса установки для git-overhooks

**Статус:** активен

## Контекст

В ходе реализиации выяснилось что текущая структура папок из ADR-01 приводит к неудобству в использовании. Также потребовался дополнительный шаг для копирования исполняемого файлы.

## Актуальная установка (`git-overhooks install`)

При установке (`git-overhooks install`) выполняются следующие действия:

- TODO: проверить процесс
- Создаётся директория `~/.git-overhooks` (глобальная для пользователя).
- В директории создаются поддиректории `bin` и `hooks.d`
- Для **каждого стандартного хука Git** (список предопределён) создаётся поддиректория `~/.git-overhooks/hooks.d/<hook>.d/`. Это делается автоматически, чтобы пользователь сразу мог складывать туда свои глобальные скрипты.
- Внутри `~/.git-overhooks/bin` для каждого стандартного хука создаётся файл-обёртка с именем хука (например, `pre-commit`) **без расширения**.  
  Содержимое обёртки:

  ```bash
  #!/bin/sh
  exec /абсолютный/путь/к/git-overhooks hook <hook-name> "$@"
  ```

  На Windows этот файл также создаётся без расширения, с shebang, и будет обрабатываться Git для Windows через его встроенный `sh`.

- Загружается конфиг файл, если он существует. Если конфигурация не загружена, то используются значения по умолчания.
- Выполняется комада `git config --global --get core.hooksPath` для получения текущей директории глобальных хуков. Сравнивается значение с сохраненном в конфигурационном файле.
  Далее обрабатываются различные варианты:
  - Если в конфигурации не задано значение - процесс просто продолжается.
  - Если в конфигурации сохранено значение, отличное от текущего, а текущее указывает на `~/.git-overhooks/bin/` - всё норм, значение в конфигурации не меняется, процесс продолждается.
  - Если в конфигурации сохранено значение, совпадающее с текущим (возможно кто-то его перезаписывает - husky\precommit\пользователь) или
  - Если в конфигурации сохранено значение, отличное от текущего, а текущее не `~/.git-overhooks/bin/` - выводится предупреждение о том, как работает процесс приложения и приглашение к использованию флага `--force`).

- **Выполняется поиск интерпретатора `sh` на Windows** (см. раздел 4). Найденный путь сохраняется в конфигурационный файл для дальнейшего использования.
- Выполняется команда:

  ```bash
  git config --global core.hooksPath ~/.git-overhooks
  ```

  Если параметр уже задан, выводится предупреждение. Для перезаписи требуется флаг `--force`. Старое значение сохраняется в конфигурационном файле (см. раздел 5) для возможности восстановления при удалении.

После этого **все** Git-репозитории пользователя будут использовать хуки только из этой директории. Локальные хуки в `.git/hooks` каждого репозитория **остаются нетронутыми**, но Git их игнорирует.
