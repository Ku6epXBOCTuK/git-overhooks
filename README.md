# goh — Git OverHooks

Управление Git-хуками без страха. Запускает хуки из нескольких источников в строгом порядке
для **всех** репозиториев пользователя, не ломая существующие хуки.

## Идея

Git позволяет задать одну глобальную папку для хуков через `core.hooksPath`.
goh кладёт туда свои обёртки и по срабатыванию хука запускает ваши скрипты по порядку:
**глобальные → Husky → `.git-hooks` → родные `.git/hooks`**.

Все репозитории пользователя получают хуки сразу, без правки каждого вручную.
Существующие хуки (Husky, `.git-hooks`, `.git/hooks`) не мигрируются и не ломаются —
goh просто запускает их по очереди.

После установки в `~/.config/goh/hooks.d/pre-commit.d/00-format.sh` создаётся встроенный
хук автоформатирования: если есть `package.json` со скриптом `format` — запускается
`npm run format` (или `pnpm`/`yarn`/`bun` по lock-файлам); если есть `Cargo.toml` — `cargo fmt`.
Если форматтер изменил файлы — коммит останавливается с просьбой просмотреть изменения.

Рядом создаётся `01-comments.sh` — контроль комментариев (см. «Правила комментариев»).

## Правила комментариев

`goh comments` проверяет staged и изменённые файлы и находит четыре вида нарушений:

1. комментарий без разрешённого ключевого слова удаляется целиком;
2. комментарий длиннее `max_lines` строк обрезается, сразу после маркера добавляется
   пометка `[cut]` — на той же строке, поэтому лимит не расходуется;
3. не-ASCII символы в комментарии — нарушение, автоматически не исправляется;
4. `to-do`, `TO-DO`, `ToDo`, `todo` → `TODO`; `fix-me`, `FixMe` → `FIXME`.

Регистр приводится автоматически. Пунктуация учитывается только если она
перечислена алиасом: `to-do` станет `TODO`, а `to.do` будет удалён как комментарий
без ключевого слова.

Не трогаются shebang, директивы (`eslint-disable`, `prettier-ignore`,
`nolint`, `go:generate`, `vim:`) и настоящая документация:

1. `///` и `//!` в Rust — это doc-комментарии по спецификации языка
2. `/** */` в `.js`/`.ts`/`.svelte`/`.vue`/`.astro`, если внутри есть хоть один признак JSDoc:
   - тег (`@param`, `@returns`, `@throws`, `@type`, `@typedef`, `@property`, `@example`,
     `@deprecated`, `@template`, `@see`, `@extends`, `@implements`, `@default`, `@enum`,
     `@private`, `@public`)
   - тип в фигурных скобках (`{string}`, `{Array<T>}`, `{?string}`)
   - ссылка (`{@link X}`, `{@linkcode}`, `{@linkplain}`)
   - markdown (```-блок, `[текст](url)`, http-ссылка)

`/** */` без этих признаков считается обычным комментарием и подпадает под правила —
достаточно одного сигнала, чтобы блок остался нетронутым.

Исключения: `.prettierignore`, иначе `.gitignore`, плюс `exclude` из конфига.

Без флагов команда только сообщает о нарушениях и ничего не пишет. Исправления
применяются по флагу `--write` — его уже передаёт хук `01-comments.sh`.

Файлы правит в рабочем дереве и **ничего не добавляет в индекс** — коммит падает,
решение за пользователем.

```sh
goh comments           # только отчёт, ничего не писать
goh comments --write   # отчёт + автофикс
goh comments --all     # проверить все отслеживаемые файлы
```

## Конфиг

`~/.config/goh/config.toml`:

```toml
[comments]
max_lines = 3
exclude = ["node_modules", "target", "dist"]

# Ключ — каноническое написание, автоматически переводится в верхний регистр.
# Значение — варианты с пунктуацией, которые считаются тем же словом.
[comments.keywords]
NOTE = []
TODO = ["to-do"]
FIXME = ["fix-me"]
```

Чтобы добавить своё слово, достаточно дописать строку:

```toml
[comments.keywords]
BUGFIX = ["bug-fix"]
```

## Установка

Требуется: Rust (для сборки) и `just`.

```sh
just install
```

Что произойдёт:

1. `cargo install --path .` — бинарь `goh` становится доступен глобально;
2. `goh install` — создаёт структуру в `~/.config/goh`, обёртки хуков,
   скрипт автоформатирования и настраивает `git config --global core.hooksPath`.

Если `core.hooksPath` уже занят другим инструментом, `goh install` без `--force`
предупредит и не тронет его.

## Отключение

```sh
goh uninstall            # снимает core.hooksPath, файлы остаются
goh uninstall --remove-files  # дополнительно удаляет ~/.config/goh
```

Откатить вручную: `git config --global --unset core.hooksPath`.

## Структура `~/.config/goh`

```txt
~/.config/goh/
├── bin/           # обёртки хуков (сюда указывает core.hooksPath)
├── hooks.d/       # ваши глобальные хуки
│   └── <hook>.d/  # по папке на каждый стандартный хук:
│       ├── 00-format.sh    # встроенный автоформаттер (pre-commit.d)
│       └── 01-comments.sh  # контроль комментариев (pre-commit.d)
└── config.toml    # настройки правил комментариев
```

## Как добавить свой хук

Сложить исполняемый скрипт (POSIX sh) в папку нужного хука, например:

```sh
~/.config/goh/hooks.d/pre-push.d/publish.sh
```

Файлы в папке выполняются по алфавиту — порядок задаётся цифровыми префиксами
(`10_lint.sh`, `20_test.sh`). Скрипту передаются аргументы от Git.

## Порядок запуска

1. **Глобальные** — `~/.config/goh/hooks.d/<hook>.d/*`
2. **Husky** — `.husky/<hook>` или `.husky/_/<hook>`
3. **`.git-hooks`** — `.git-hooks/<hook>` (версионируемые хуки проекта)
4. **Родные** — `.git/hooks/<hook>`

Любой ненулевой код выхода останавливает цепочку и возвращается Git'у.

## Терминология

- **Глобальные** — хуки пользователя, действуют везде.
- **Husky** — хуки из `.husky/`.
- **`.git-hooks`** — версионируемые хуки проекта (в git).
- **Родные** — хуки, лежащие в `.git/hooks` до установки goh.

## Разработка

```sh
just dev             # cargo run -- install -vvvv (без глобальной установки)
just git-show-hooks  # показать текущий core.hooksPath
```
